# الخزنة والذاكرة وGit

## العقل هو الملفات

لا توجد للدوكسوغراف ذاكرة سرية مستقلة. ما يتعلمه عن صاحب الخزنة أو المشروع أو طريقة العمل يجب أن يعيش في Markdown مناسب:

- القاعدة الدائمة في ملفات العقل.
- الذائقة المستقرة في [[٠١-صاحب الخزنة والذائقة]].
- الحالة المتغيرة في [[حالة الخزنة]].
- القرار المنهجي في [[سجل قرارات العقل]].
- ما حدث في الجولة في [[سجل-الجلسات]].
- البنية المعرفية الحية في [[خريطة-المعرفة]].

لا تكرر المعلومة نفسها في كل موضع. اجعل لكل ملف وظيفة.

## اقتصاد الاستدعاء

لا تُقرأ هذه المواضع كلها في بداية كل جلسة. `INVOKE_AGENT.md` يحمل النواة الدائمة ويوجه إلى الملف الذي تحتاجه المهمة:

- [[حالة الخزنة]] حالة ساخنة مختصرة، لا أرشيفًا للخيوط السابقة.
- [[خريطة-المعرفة]] تُقرأ لاختيار باب أو بناء جسر عبر الشبكة، لا لتحرير ملف معروف.
- [[سجل-الجلسات]] يُستدعى بآخر جلسة كاملة عند الاستئناف، وبمدى أوسع عند التدقيق التاريخي فقط.
- [[سجل قرارات العقل]] يُقرأ عند تغيير قاعدة أو مراجعة أصلها.
- [[ذاكرة التعلم]] تُستدعى بالبطاقة ذات الصلة، وتُقرأ كاملةً حين تتغير معماريتها أو يلزم حل تعارض بين بطاقات.

متى دخل ملف بروتوكولي أو معرفي في النطاق، يُقرأ كاملًا. تقليل الاستدعاء يعني تقليل عدد الملفات غير ذات الصلة، لا العمل من مقتطفات مبتورة. وإذا تكرر الاحتياج إلى معلومة تشغيلية قديمة، تُنقل خلاصة نافذة منها إلى الحالة بدل جعل الأرشيف قراءةً يومية.

## Git بوصفه جهاز استشعار

افحص Git قراءةً فقط قبل أول تعديل في كل جلسة تمس الخزنة، ومن خلال قائمة سماح صريحة للمحتوى الذي يجوز للدوكسوغراف رؤيته. ابحث عن تغيير دلالي: فكرة، سؤال، اعتراض، ملف جديد، أو توسع. لا تفسر تعديلًا إملائيًا أو ملف واجهة بوصفه فضولًا معرفيًا. قائمة الفحص الدلالي لا تحدد نطاق النسخ الاحتياطي؛ Syncthing وGit يحفظان الخزنة كلها، بما فيها المواضع التي لا يقرأها الوكيل.

### خط أساس الجولة

- لقطة Git السابقة لأول كتابة هي الحد الفاصل. كل فرق موجود فيها **تغيير موروث**، سواء صنعه صاحب الخزنة أو بقي من جولة سابقة؛ وكل فرق ينشأ بعدها عن العمل المأذون **تغيير الجولة**.
- أخبر صاحب الخزنة بالتغييرات الموروثة قبل لمسها، واجمع المتشابه منها في وصف واضح، ثم اقترح لكل مجموعة: إبقاءً، أو دمجًا، أو تأجيلًا. لا تعدّلها ولا تدرجها تلقائيًا في التسليم قبل موافقته.
- إذا منح الطلب الجاري إذنًا صريحًا للفعل نفسه على الملف المتغير، يكون الإذن قائمًا بعد الإخبار ولا يلزم سؤال ثانٍ. أما العمل المستقل الذي لا يمس التغيير الموروث فيجوز أن يستمر.
- لا يُعاد تصنيف تعديلات الجولة نفسها بوصفها تغييرات موروثة، ولا يُطلب الإذن بها مرة أخرى ما دامت باقية داخل نطاق الطلب. وإذا ظهر تعديل خارجي جديد أثناء الجولة وتداخل مع ملف يعمل عليه الوكيل، يعامل كتعارض حديث ويقف الوكيل قبل الكتابة فوقه.
- إذا كان خط الأساس نظيفًا، قل ذلك باختصار وابدأ. وإذا لم يكن نظيفًا، فلا تدّع أن الجلسة بدأت من شجرة نظيفة.

Git دليل على الحركة وطبقة تاريخ، لا ذاكرة بديلة.

### من الفرق إلى طلب التحرير

ابدأ بأسماء الملفات المتغيرة في قائمة سماح محددة، ثم فرق موضعي للملف المعني؛ ميّز التغييرات غير المثبتة والمهيأة، وعند صلة الطلب بالتاريخ اقرأ سجل الملف المحدد لا سجل الخزنة كله. ابحث عن «ايجنت» في الأسطر المضافة أو المتغيرة مع سياق قصير؛ الكلمة الموجودة في نص حُذف أو في مثال بروتوكولي ليست تكليفًا جديدًا.

التوجيه الصريح يجيز الفعل الذي سمّاه فقط. بلا توجيه، أو عند غموضه، يُسأل صاحب الخزنة هل يريد تحسين التغيير أم إبقاءه. لا تُستنتج هوية الكاتب من Git وحده، ولا يُعاد السؤال عن تغييرات الجولة المأذون بها. الملفات غير المتتبعة ليس لها فرق سابق موثوق؛ يقال ذلك ولا يُخترع نص قبلها. تجنب إعادة التنبيه إلى فرق سبق أن حُسم موقفه ما لم يتغير.

### فحص المحتوى عند محطات التقدم

أداة `tools/Test-Library-Content.ps1` فحص محلي للقراءة فقط، مستقل عن فحص Git والمزامنة التقني. يشغَّل عند اكتمال كوكبة أو دفعة تحرير كبيرة، أو خلل ظاهر، أو طلب مباشر. لا يُضاف إلى الاستدعاء التلقائي ولا إلى متابعة ساعية أو مهمة مجدولة. المرجع المقروء لآخر نتيجة هو [[مرآة الخزنة — ما الذي بقي خارج الضوء]].

يدخل الفاحص جذورًا مسموحة مسماة فقط، ولا يجتاز جذر الخزنة ولا أرشيف الاسترداد ولا الروابط الرمزية. فحص المجلدات الحالية مباشر غير متداخل؛ المجلدات الفرعية والإضافات الشخصية خارج نطاق النسخة الأولى. الهدف غير الموجود في النطاق «غير محسوم»؛ قد يكون فرعًا مقصودًا لم يُكتب أو ملفًا خارجه، وليس رابطًا مكسورًا يقينًا.

يفصل التقرير بين خلل تقني قابل للفحص، ومادة تستدعي قراءة بشرية: تكرار نصي، وقصر، وعزلة داخل نطاق الفحص. لا يصدر أمر حذف ولا يغيّر مقالًا. يُختار إصلاح محدود بعد قراءة الملف، ويُعرض الحذف أو الدمج على صاحب الخزنة أولًا. لا يثبت الفاحص صحة اقتباس أو نسبة تاريخية.

لا يؤسس سجل شواهد مستقل الآن؛ تأجيله قرار صريح في [[خارطة تطوير المكتبة — من التراكم إلى الاستعمال]].

### التسليم النظيف

لا تعمل `commit` أو `push` أو `reset` أو `rebase` أو تغير التاريخ إلا بطلب صريح. لا تنشئ commits مرحلية أثناء الكتابة: بعد اكتمال العمل والتحقق منه، اعرض الحصيلة، ثم يكون `commit` و`push` خطوة تسليم واحدة إذا صدر التفويض الختامي. يشمل الحفظ النهائي كل محتوى الخزنة الموافق على حفظه، ولا يُستبعد مجلد لمجرد أن الوكيل ممنوع من قراءته؛ يمكن إدراجه بصمت من غير عرض أسمائه أو محتواه. تظل التغييرات الموروثة المرفوضة خارج التسليم. بعد نجاح الدفع افحص النظافة عدديًا أو عبر المسارات القابلة للقراءة، ولا تكشف أسماء موضع محظور أثناء التحقق.

## Syncthing وGitHub

المزامنة اليومية ثنائية الاتجاه بين Windows وAndroid تتم عبر Syncthing. الحاسوب وحده يدير Git وGitHub، ولا تستخدم أوامر Git على الهاتف بعد بدء المزامنة.

- `.git` لا ينتقل إلى الهاتف.
- كل محتوى الخزنة المعرفي والشخصي يدخل المزامنة افتراضيًا؛ الاستبعادات محصورة في حالة الأجهزة والملفات التقنية المؤقتة المعلنة في `.stignore.shared`.
- Syncthing يحتفظ بنسخ Staggered لمدة 60 يومًا على الحاسوب.
- أي ملف `sync-conflict` يوقف لقطة Git حتى يُفحص.
- لا يُحذف تعارض قبل مقارنة الأصل والنسخة.
- GitHub يحفظ نقاط الرجوع، ولا يحل محل المزامنة الفورية.

الدليل التشغيلي: [[دليل-مزامنة-الخزنة]].

## اقتصاد الذاكرة

قبل إنشاء ملف جديد، اسأل:

- هل توجد ملاحظة تؤدي الوظيفة نفسها؟
- هل تستحق البذرة صفحة أم سطرًا في `روابط_تحتاج_توسعة`؟
- هل مركزها جملة لا تنطبق على خمس صفحات قائمة؟
- هل ستغير قراءة عقدة أخرى؟
